Universal Hotkey Manager for Skyrim SE-AE

스캔. 감지. 관리.

Universal Hotkey Manager for Skyrim SE-AE(UHM)은 스카이림의 단축키를 하나의 인게임 관리 창에서 확인할 수 있게 해 주는 ESP 없는 SKSE 플러그인입니다.

활성 모드 구성을 스캔하여 스카이림 기본 조작, 모드 설정 파일, MCM 설정, 스크립트, 네이티브 플러그인, ReShade, ENB, Community Shaders 등에서 키보드·마우스·게임패드 바인딩을 찾아냅니다. 카테고리별로 감지된 바인딩을 확인하고, 추정 소유자와 출처를 보며, 스카이림의 활성화 상황을 고려해 실제 충돌을 식별할 수 있습니다.

주요 기능

  • 모든 단축키를 한곳에서 — 키보드, 마우스, 게임패드 바인딩을 네이티브 인게임 UI에서 확인합니다.
  • 상황 인식 충돌 감지 — 양쪽 활성 컨텍스트가 모두 확정되고 실제로 겹칠 때만 충돌로 표시합니다. 불명 또는 추정 컨텍스트가 포함되면 주황색 중복으로, 확정적으로 분리된 컨텍스트는 비충돌로 처리합니다.
  • 폭넓은 모드 지원 — 지원되는 INI, JSON/JSONC, TOML, YAML, XML, CFG, CONF, SETTINGS, PROPERTIES 파일과 관련 MCM, 스크립트, 아카이브, 플러그인 근거를 스캔합니다.
  • 기기 맵 — 키보드, 마우스, 게임패드 레이아웃에서 바인딩을 직접 확인합니다.
  • 안전한 지원 설정 편집 — 관리 창에서 유효한 느슨한 설정 파일의 바인딩을 직접 수정할 수 있습니다. DirectInput, SKSE 통합 코드, Windows VK, XInput/controlmap, ReShade, Community Shaders 및 지원되는 기호 형식을 원본 규칙에 맞춰 저장하며, 손실 없이 표현할 수 없는 변환은 거부합니다. 최초 수정 시 .uhi.bak 백업을 만든 뒤 원자적으로 파일을 교체하고 재스캔합니다.
  • 스카이림 사용자 키 정확히 표시 — 스카이림 자체 조작 메뉴에서 바꾼 키는 현재 런타임 ControlMap 값으로 정확히 표시합니다. 유효한 루트 ControlMap_Custom.txt가 있으면 스카이림 기본 조작은 모두 읽기 전용이며, 바이너리 사용자 맵이 없을 때만 현재 키와 정확히 일치하는 loose controlmap.txt 바인딩을 변경할 수 있습니다.
  • 캐시 기반 증분 갱신 — 최초 전체 스캔은 직접 시작합니다. 이후 완료된 세이브 로드 때만 캐시 기반 증분 확인을 한 번 수행하며, 창을 열기만 해서는 재스캔하지 않고 프레임 단위 감시도 하지 않습니다.
  • 세이브와 독립된 결과 저장 — 성공한 스캔 결과는 Skyrim 세이브 없이 UHM이 즉시 저장합니다. 활성 단축키가 새로 생기거나 바뀐 경우에만 무딤 없는 개수 알림을 한 번 표시합니다.
  • 리포트 생성 — 스캔이 성공하면 상세 JSON 리포트를 생성합니다.

사용 방법

  1. 기본 단축키인 Delete로 관리 창을 엽니다.
  2. Options에서 스캔을 시작합니다.
  3. 바인딩, 소유자, 출처, 활성화 상황, 충돌을 검토합니다.
  4. 카테고리 탭, 기기 맵, 필터를 사용해 원하는 항목을 찾습니다.
  5. Options에서 관리 창을 여는 단축키, 전체 UI 글자 크기, 인터페이스 언어, UI 창 투명도를 변경할 수 있습니다.
  6. 장치 키를 좌클릭하면 명칭 변경, 우클릭하면 명칭 변경/단축키 변경 메뉴가 열립니다. 목록에서는 행의 변경 버튼을 사용합니다.
  7. ESC는 UHM을 닫고, 편집·입력 팝업에서는 저장하지 않고 해당 팝업을 취소합니다.

스카이림 기본 조작을 UHM에서 변경하려면

controlmap.txt는 사람이 읽고 편집할 수 있는 스카이림 입력·컨텍스트 원본 정의입니다. MO2 가상 Data에서 적용되는 loose 파일 경로는 보통 Data/Interface/Controls/PC/controlmap.txt입니다. 반면 게임 루트의 ControlMap_Custom.txt는 Skyrim의 System > Controls 메뉴에서 키를 바꿀 때 게임이 생성하는 별도의 바이너리 사용자 덮어쓰기 파일이며, 메모장으로 직접 편집하는 파일이 아닙니다.

UHM은 이 사용자 변경 결과를 현재 런타임 값으로 정확히 표시하지만, 유효한 ControlMap_Custom.txt가 있는 동안에는 스카이림 기본 조작을 읽기 전용으로 표시합니다. 설치한 loose controlmap.txt를 UHM에서 관리하려면 다음 순서로 정리하세요.

  1. Skyrim을 완전히 종료합니다.
  2. SkyrimSE.exe 옆의 ControlMap_Custom.txt를 백업한 뒤 삭제합니다.
  3. 사용하려는 게임 버전용 Data/Interface/Controls/PC/controlmap.txt가 MO2 가상 Data에서 최종 승리하는지 확인합니다.
  4. 게임을 실행하고 UHM 전체 스캔을 진행합니다. 현재 값과 일치하는 loose controlmap 바인딩은 UHM의 백업 보호와 함께 변경할 수 있습니다.

Custom 파일을 삭제한 뒤 적용되는 값은 반드시 바닐라 기본값이 아니라, 현재 MO2에서 최종 적용되는 mod-provided controlmap.txt 값입니다. 게임을 실행하기만 해서는 Custom 파일이 다시 생기지 않지만 Skyrim의 Controls 메뉴에서 키를 다시 바꾸면 새로 생성되며, 이때 UHM은 해당 스카이림 조작을 다시 읽기 전용으로 처리합니다. 게임 버전과 맞지 않는 controlmap은 입력 컨텍스트 구조가 달라 조작 이상이나 시작 실패를 일으킬 수 있으므로 반드시 현재 런타임용 파일을 사용하세요.

창 열기 단축키 복구

Delete가 겹쳐 UHM을 열 수 없다면 게임을 끈 뒤 Data/SKSE/Plugins/UniversalHotkeyManager.ini를 편집하세요. MO2에서는 보통 Overwrite/SKSE/Plugins/UniversalHotkeyManager.ini에 생성됩니다. ToggleKey=0xD3는 DirectInput 스캔코드 기준 Delete이며 WindowOpacity=0.90은 본체 창 배경에만 적용됩니다. INI를 삭제하면 Delete·100% 글자 크기·90% 투명도·자동 언어로 복구됩니다.

캐시 위치와 삭제

Data/SKSE/Plugins/UniversalHotkeyManager/scan-cache-v1.bin
Data/SKSE/Plugins/UniversalHotkeyManager/last-scan-v1.bin

MO2에서는 보통 Overwrite/SKSE/Plugins/UniversalHotkeyManager/에 있습니다. 첫 파일은 파일별 스캔 캐시, 둘째는 즉시 복원할 화면 결과입니다. 게임을 끈 상태에서 둘 다 삭제하면 다음 전체 스캔 때 다시 생성됩니다.

요구 사항

  • Skyrim Special Edition / Anniversary Edition
  • SKSE64
  • Address Library / CommonLib 호환 게임 런타임
  • SKSE Menu Framework 2.1.1 이상
  • SKSE 플러그인에 필요한 Microsoft Visual C++ Redistributable

참고

UHM은 모든 정적 값을 확정 충돌로 표시하지 않고, 실제로 유효한 활성 바인딩을 중심으로 보여 주도록 설계되었습니다. 읽기 전용 근거도 필요한 경우 표시하지만, 직접 편집할 수 있는 것은 지원되는 활성 설정 출처에 한정됩니다.

자동 언어는 Windows 사용자 UI 언어와 로케일을 함께 확인하며 한국어·영어·중국어를 지원합니다. 옵션에서 수동 고정할 수도 있습니다. UTF-8 모드명과 경로는 Windows의 선택적 시스템 전체 UTF-8 설정 없이도 지원합니다. UHM은 SKSE Menu Framework의 PrimaryFont와 다른 설정은 보존하고, 현재 UI 언어에 필요한 한국어 또는 중국어 글리프 범위만 자동으로 활성화합니다. 설정이 변경된 경우 글꼴 아틀라스 재생성을 위해 안내 후 스카이림을 한 번 재시작하세요. 선택된 폰트 자체에는 해당 글자가 포함되어 있어야 하며 Windows 폰트는 UHM에 재배포하지 않습니다.

Escape를 누르면 관리 창이 닫힙니다. 명칭 또는 단축키 입력 팝업이 활성화된 동안에는 창을 닫는 대신 해당 입력을 취소합니다.
