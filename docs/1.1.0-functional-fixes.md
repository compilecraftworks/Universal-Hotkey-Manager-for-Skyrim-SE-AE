# 1.1.0 functional regression fixes

The 1.0.9 audit identified five issues: save deletion incorrectly entering the loading state, imprecise configuration writes, JSON action deduplication, premature MCM success, and three missing Chinese UI glyphs.

## Editing compatibility

JSON/JSONC scan records keep an escaped object/array pointer in the existing `settingSection` field (`json:/parent/setting`). The writer resolves that pointer again and checks the previous value. Whitespace changes and an unrelated sibling edit therefore do not prevent a valid edit. Source bytes outside the selected value are preserved. Comments, trailing commas, array parents, escaped property names, numeric/scalar/array values, legacy unique line-based records and existing non-JSON formats remain supported.

Ambiguity is rejected only when the target cannot be uniquely identified, such as duplicate properties in the same object or an old record without a path matching two settings on its recorded line. The scanner and registry retain different structural identities even when action labels or hotkeys match.

Snapshot/cache semantics are invalidated once. The serialized record layout has not changed, so schema-11 history from 1.0.9 is still read and upgraded on its next save. Original `.uhi.bak` files are retained.

## MCM completion and ownership

Dispatch reports pending progress and releases the editor as before. The asynchronous result is verified on the game task thread after the VM callback. Success/history for a live edit requires the requested value to match. Existing property writes and optional file-to-MCM synchronization remain supported with explicit notices.

A completed no-op/rejected live change restores its linked document using the expected just-written value. An unfinished handler has a 30-second deadline. Its file is not rolled back while Papyrus might still apply the queued request; the user receives an unconfirmed-result notice instead. The VM dispatch itself cannot be cancelled. Loading clears the old pending operation before runtime objects revert.

There is at most one pending MCM operation and one queued maintenance task. The existing opening-key polling thread schedules maintenance; there is no added permanent thread and no detached thread per edit. The callback holds only a weak receipt, not an operation, completion closure or Papyrus object. Verification resolves the live property again instead of retaining raw engine pointers. A result from an earlier editor can publish its notice but cannot close or overwrite a newer editor.

## Validation

The clean SE/AE build and all 27 automated tests passed on 2026-09-19.

- All existing configuration, serializer, backup, cache, detector, renderer, menu and input tests remain in the suite.
- New integration cases cover a sibling value changing between scan and edit, duplicate names/bindings, JSON reformatting, JSONC/comments/arrays, exact backup restore, stale target rejection, comments/string contents and UTF-8 BOM/CRLF preservation.
- The previous history schema is tested independently of scan-cache invalidation.
- MCM receipt checks cover dispatch without completion, success, no-op, missing target, timeout and late callbacks. A 1,000-cycle ownership check confirms that weak callbacks do not retain receipts.
- The font test checks all Korean/Chinese characters present in the actual UI source. Its ImGui allocation tracker checks 20 font/context creation/destruction cycles after warmup. Retained allocation remains at the one-time 10,332-byte character-range cache, with no increase per cycle; the atlas remains 4096 × 2048 on the test PC.
- First-open popup cleanup and 100 menu/popup reopen cycles remain covered. Escape checks now use explicit failure reporting under `NDEBUG` too.

These are host-side tests and source checks. They do not replace testing Skyrim, actual Papyrus handlers, MO2 combinations or GPU allocations in the game. No universal leak-free or mod-compatibility claim is made.
