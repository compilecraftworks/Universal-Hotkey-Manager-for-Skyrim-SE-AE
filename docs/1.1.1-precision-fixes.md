# 1.1.1 precision fixes and validation

The 1.1.0 audit reproduced 14 issues. This update keeps the supported editors and detection paths while narrowing writes to the intended source and removing quadratic conflict storage.

| Audit item | Implemented correction | Verification |
|---|---|---|
| F01 MCM ownership | Require the matching script or registered mod before selecting integer, global or array targets. | Actual production selection code compiled with engine stand-ins; unrelated scalar/array writes fail, owned writes and stale-value guards remain working. |
| F02 INI sections | Resolve section plus setting again, then verify the previous value. | Reordered sections change only Alpha; duplicate and stale targets are refused. |
| F03 Modifier scope | Group compound fields and modifier flags by JSON object, INI/TOML section or YAML parent. XML modifiers stay inside their element context. | JSON, INI, TOML array tables, YAML, modifier aliases and existing XML controls. |
| F04 Scalar preview | Preserve separately stored modifiers when capturing a new main key; reject unsupported modifier changes. | Main-key changes, same-modifier capture, different-modifier rejection and unbinding. |
| F05 Large configs | Inspect the full candidate file within the existing 16 MiB file-size policy before caching a negative result. | A 620,013-byte INI with its only binding after 256 KiB is found. |
| F06 Load refresh | After an established scan, queue one cache-aware scan after load/new game to enumerate new files and recapture live values; wait for a cancelled scan to finish. Reject obsolete queued capture generations. | New-file discovery with unchanged-file cache hits; load scheduling reviewed in source. Real save-to-save VM behavior requires in-game validation. |
| F07 Option zero | Accept SkyUI keymap ID 0 only with matching page-zero and keymap-type buffer evidence. | Valid zero, uninitialized zero, wrong option type/page and legacy positive IDs. |
| F08 API ordering | Queue the final open/close request even while visible; opening supersedes an unposted close. | 1,000 production API queue cycles plus existing native lifecycle tests. |
| F09 Conflict memory | Share group membership and compute peer lists when requested. Compute statuses by context profiles and reuse the analysis when publishing the view. | Exhaustive pairwise comparison, all 4,096 entries and 4,095 peers retained, allocation accounting below. |
| F10 UTF-16 | Retain detection and mark unsupported byte-preserving writes read-only. | UTF-16 binding remains visible and cannot advertise editing. |
| F11 JSON backup identity | Exclude formatting-dependent line numbers when a structural JSON locator exists. | Multiple history entries across JSON reflow resolve the same source. |
| F12 BOM | Strip a first-line UTF-8 BOM before reading UHM's General section. | Disabled opening key and changed key value are honored. |
| F13 Non-finite settings | Reject NaN/infinity in parsing and save validation. | Finite defaults after malformed input; invalid saves refused. |
| F14 Action aliases | Exclude the binding value from alias identity and migrate previous keys. | Rebinding/reflow preserves identity; 1.1.0 key migration. |

SkyUI page/type handling follows [SKI_ConfigBase.psc](https://github.com/schlangster/skyui/blob/master/dist/Data/Scripts/Source/SKI_ConfigBase.psc). Existing property fallback remains available when no usable keymap option is proven.

## Validation on 2026-09-19

- Clean x64 SE/AE build: passed. CommonLibSSE-NG 6.7.0 and its pinned dependency closure are unchanged. SE/AE defines are enabled and VR is disabled; upstream therefore selects the exclusive flat layout.
- Full release-mode suite: **31/31 passed**, including actual ImGui popup cleanup, mouse/input lifecycle, serializers, writers, scanners, backup/cache compatibility and Korean/Chinese Windows font coverage.
- Fully instrumented core build with MSVC AddressSanitizer: **10/10 selected executables passed** (precision, forum, functional, generic scanner, runtime API, MCM target, registry, view, serializer and config writer). The engine-only MCM stand-ins do not validate the real Papyrus ABI.
- At 4,096 same-key records, conflict-analysis peak additional requested C++ allocation fell from **177,187,412 bytes** in the audit to **310,045 bytes**. View construction plus a complete peer query peaked at **1,114,298 bytes**. Release returned to baseline at every tested size. These are allocation-counter values, not process RSS.
- 1,000 JSON/registry/view creation/destruction cycles retained **0 additional bytes**. The existing 20-cycle font test retained the unchanged one-time **10,332-byte** character-range cache, with no per-cycle increase; atlas 4096 × 2048.
- DLL metadata is 1.1.1 / 1.1.1.0. The x64 binary retains the SKSE and four menu API exports; it does not import a standalone ImGui or sanitizer DLL.

## Local build error correction

During the first incremental run, Ninja had recorded zero header dependencies because its cached Korean `/showIncludes` prefix was decoded incorrectly. The changed view layout was linked with old test objects, producing the reported test access violation. A clean build removed the mismatch. CMake now probes the compiler's actual prefix without decoding its bytes and uses the same requested language for compilation. It also handles a missing English language pack. The forum test now records 19 project header dependencies; touching `HotkeyViewModel.h` schedules recompilation of that test and the affected core files.

The additional sanitizer run initially failed before program startup because its runtime DLL was unavailable through the test launcher path. The final sequential run used the installed MSVC runtime directory in native Windows path notation; all 10 tests then passed. Sanitizer binaries remain under the local `build/asan` directory and are excluded from distribution.

The prefix probe uses CMake's documented [raw-output encoding](https://cmake.org/cmake/help/latest/command/execute_process.html) and [compiler launcher](https://cmake.org/cmake/help/latest/prop_tgt/LANG_COMPILER_LAUNCHER.html) facilities. Release packaging retains the clean-build requirement and preserves historical archive checksums.

These are host-side checks. Skyrim, real mod combinations, save transitions, actual Papyrus handlers and GPU allocations still require in-game testing. The results do not establish universal absence of regressions or leaks.
