# UHM 1.0.8 opening crash — 2026-09-19

## Confirmed local regression

The 1.0.8 change calls `ImGui::ClosePopupToLevel(0, false)` after
`ImGui::NewFrame()` whenever the host resets its input. This happens on the
first opening, when `OpenPopupStack.Size == 0` and its storage is null.

The pinned ImGui 1.91.9 implementation requires `remaining < OpenPopupStack.Size`
and reads `OpenPopupStack[remaining]`. Release builds omit the assertion but
still read entry zero. Passing `false` only disables focus restoration; it
does not skip that read. The call was absent in 1.0.7.

Primary implementation: [ImGui v1.91.9](https://github.com/ocornut/imgui/blob/v1.91.9/imgui.cpp#L11669).
The source is also present in the repository's pinned vcpkg build tree.

An isolated Windows executable linked to the same release `imgui.lib` used
by UHM, built with `/O2 /DNDEBUG /MD`, reproduced:

```text
ImGui=1.91.9; first-frame popup stack size=0, data=0000000000000000
1.0.8 ClosePopupToLevel(0, false): exception=0xC0000005
```

The probe catches the fault with SEH to avoid a crash dialog. It performs the
actual ImGui context/font/input/NewFrame sequence, not a simulated popup stack.
See `output/uhm-1.0.8-open-crash/probe.cpp` and `probe.log`.
This demonstrates a sufficient crash cause consistent with the report; no
reporter crash log or actual Skyrim execution was available this turn.

## Local correction and validation

The host now invokes the shared `UHI::ResetNativeMenuPopups` helper, which uses
`ImGui::ClosePopupsOverWindow(nullptr, false)`. The upstream wrapper handles an
empty stack and closes all remaining popups, including modals, when present.
It runs in the same host context and at the same frame boundary. The wheel
ownership/lifecycle fix from 1.0.8 remains in place.

The new test links actual pinned ImGui and exercises the production helper:
fresh first frame, repeated empty cleanup, modal plus nested popup, a popup
not yet submitted to BeginPopup, stale queued input, and 100 reopen cycles.
The earlier lifecycle test did not create an ImGui context or cover this call.
